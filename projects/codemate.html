CodeMate

GitHub PR의 변경 코드를 AI로 분석하고, 코드 위치를 공유하며 논의한 리뷰를 GitHub PR에 등록할 수 있는 공동 리뷰 서비스입니다.

서비스 열기 ↗

2026.02 - 현재 · Frontend / Full-stack

TypeScriptReactNext.js App RouterTanStack Query
사용자
GitHub Pull Request(PR)를 검토하는 개발자와 소규모 팀
해결 과제
GitHub PR을 리뷰할 때 변경 코드의 맥락을 파악하고, 원격 팀원과 같은 파일·줄을 보며 의견을 나눈 뒤 그 결론을 PR에 남기는 과정이 번거롭습니다.
내 기여
GitHub PR 동기화·diff 화면·AI 코드 리뷰를 구현하고, 코드 위치를 공유하는 공동 리뷰방에 실시간 채팅과 음성 대화를 연결했습니다. 선택한 의견을 GitHub PR 리뷰로 등록하는 흐름도 만들었습니다.
결과
한곳에서 PR 변경 코드와 AI 리뷰를 확인하고, 같은 코드 위치를 보며 채팅으로 논의할 수 있습니다. 음성 기능이 활성화된 경우 함께 대화하고, 선택한 의견을 GitHub PR 리뷰로 등록해 상태를 확인할 수 있습니다.

AI 코딩 도구를 활용해 개발했고, 설계·성능 측정·검증은 직접 수행했습니다.

Case studies

문제 해결

01

큰 PR에서 첫 코드가 늦게 보임

문제

변경 파일이 많은 PR에서 보이지 않는 코드까지 한꺼번에 그리면 화면 요소가 많이 쌓입니다. PR로 돌아왔을 때 첫 코드 행이 보이기까지 오래 걸렸습니다.

해결

파일 목록과 제목은 먼저 보여주되, 화면 밖 diff의 파싱·DOM 생성은 미뤘습니다. 스크롤로 가까워진 파일의 본문만 만들고, 선택 중이거나 댓글을 쓰는 파일은 남겨둡니다. 아직 표시하지 않은 영역은 높이를 보존해 스크롤 위치가 튀지 않게 했습니다.

확인

같은 운영 PR에서 변경 전후 각 20회 순차 측정한 결과, PR로 돌아온 뒤 첫 코드 행이 보이기까지 걸린 시간 중앙값은 3.259초에서 2.334초로, 그 시점의 DOM 요소 수는 18,163개에서 1,766개로 줄었습니다.

02

대시보드의 한 영역이 늦으면 전체가 기다림

문제

통계 카드, 차트, 최근 PR 목록을 페이지에서 한꺼번에 조회하고 모두 끝난 뒤 화면을 반환했습니다. 최근 PR 조회가 늦어지면 이미 준비된 통계와 차트도 함께 기다려야 했습니다.

해결

통계, 차트, 최근 PR을 각각 데이터를 조회하는 Server Component로 분리하고 별도의 Suspense 경계와 스켈레톤을 뒀습니다. 서버는 준비된 영역부터 전달할 수 있고, 느린 영역만 해당 자리에서 기다립니다. 차트에 필요한 두 조회는 차트 영역 안에서 병렬로 실행합니다.

확인
  • 로컬 프로덕션 빌드 전후(각 15회): 인증·조회 경로 개선을 포함한 변경 후 대시보드 LCP p75 4.948초 → 4.236초(14.4% 감소)
  • 영역별 Suspense 비교(최근 PR에 동일한 3초 지연, 각 3회): 통계 카드 LCP 중앙값 4.194초 → 1.386초(약 67% 감소)
03

같은 PR의 AI 리뷰가 중복 실행될 수 있음

문제

동시에 들어온 AI 리뷰 요청은 화면의 버튼 비활성화만으로 중복 실행을 막을 수 없습니다.

해결

화면에는 대기 상태를 바로 표시하고, 서버는 진행 중인 리뷰를 조회합니다. PostgreSQL 부분 고유 인덱스로 PR마다 PENDING 또는 IN_PROGRESS 리뷰를 한 건만 허용하고, 동시 삽입 충돌은 기존 작업이 진행 중인 경우로 처리합니다.

04

PR 기본 정보가 코드 로딩을 기다림

문제

변경 파일과 diff 요청을 함께 기다리면 이미 조회 가능한 PR 제목·상태까지 늦게 보입니다.

해결

서버에서 접근 권한을 확인하며 PR 기본 정보를 먼저 전달합니다. 변경 파일은 클라이언트에서 따로 불러오고, diff 뷰어도 필요할 때 가져와 코드 영역의 로딩·오류를 독립적으로 표시합니다.

05

함께 본 코드와 논의 결과를 PR에 연결하기 어려움

문제

원격으로 PR을 검토할 때는 상대가 보고 있는 파일·코드 줄을 말로 맞춰야 했습니다. 대화 중 정리한 의견을 GitHub PR에도 남기려면 다시 옮겨 적어야 했습니다.

해결

선택. 파일·스크롤·코드 위치와 음성 연결 신호는 Socket.IO로 공유하고, 음성 통화는 WebRTC로 처리했습니다. 채팅은 CodeMate에 저장해 재접속 시 복원하며, 사용자가 선택한 리뷰만 GitHub PR에 게시합니다.

해결. 방 참여자만 최대 4명까지 음성에 들어갈 수 있고, 음성 기능은 기능 플래그로 제어했습니다. 일반 리뷰는 PR 리뷰 본문에, 코드 줄 리뷰는 최신 diff에서 위치를 확인한 뒤 줄 댓글로 등록했습니다. 게시 상태를 보여 주고 실패하거나 오래 멈춘 요청은 다시 시도할 수 있게 했습니다.

확인

Socket·음성 훅 테스트에서 참여 자격, 4명 제한, 시그널 전달, 마이크 전환과 연결 종료 시 정리를 확인했습니다. GitHub API를 모의한 테스트에서는 일반/코드 줄 리뷰 등록, 오래된 코드 위치 거부, 중복 등록 복구와 권한 오류를 확인했습니다.

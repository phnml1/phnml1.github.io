## 프로젝트 한 줄 설명

GitHub PR의 변경 파일을 읽고 AI 리뷰를 요청해 결과를 확인하며, 팀원과 같은 코드를 보며 대화할 수 있는 코드 리뷰 웹 서비스입니다.

## 내가 구현한 핵심 기능

- **변경 파일 탐색:** 파일이 많은 PR에서는 원하는 코드를 찾고 읽기 어렵습니다. PR 목록에서 대상을 고른 뒤 파일 목록과 코드 차이를 볼 수 있게 했고, 작은 화면에는 파일 선택 메뉴를 두었습니다.
- **AI 코드 리뷰 요청·결과 확인:** 분석이 끝나기 전에는 사용자가 요청이 접수됐는지 알기 어렵습니다. 요청 후 대기·분석 중·완료·실패 상태를 구분하고, 진행 중에는 리뷰 상태를 다시 조회합니다. 완료되면 요약·점수·발견한 문제를 보여주고, 실패하면 이유와 재시도 버튼을 제공합니다.
- **리뷰 현황 대시보드:** 여러 PR의 진행 상황을 하나씩 열어보지 않도록 진행 중인 PR, 주간 리뷰, 코드 품질 통계와 최근 PR·차트를 모았습니다. 서버 컴포넌트에서 데이터를 읽고 카드·차트·목록에 별도 로딩 경계를 두어 준비된 영역부터 표시합니다.
- **공동 리뷰방:** 원격으로 함께 검토할 때는 상대가 어느 파일과 코드 위치를 보는지 알기 어렵습니다. 별도 리뷰방에서 Socket.io로 참여 상태와 파일·스크롤 위치를 공유하고, 코드 줄에 연결한 대화를 주고받게 했습니다. 상대 위치로 이동하거나 따라갈 수 있으며, 코드 버전이 다르면 이동을 막고 안내합니다. 일반 PR 댓글·알림은 이 방식으로 동기화하지 않습니다.

## 대표 기술 문제

### Problem 01 - 변경 파일이 많은 PR에서 코드가 늦게 보이는 문제

모든 파일의 diff를 한 번에 파싱하고 표로 만들면 화면 밖 코드까지 DOM에 쌓입니다. 파일 목록을 받은 뒤에도 사용자가 첫 코드 행을 확인하기까지 시간이 걸렸습니다.

### Solution 01 - 파일별 diff 본문을 가까워질 때 표시

파일 목록과 헤더는 유지하고, 화면에서 약 800px 이내에 들어온 파일의 diff 본문만 생성합니다. 선택한 파일이나 댓글 작성 중인 파일은 화면 밖이어도 유지합니다. 표시하지 않은 본문에는 측정 높이 또는 추정 높이의 빈 공간을 남기고, 파일·줄 이동 대상은 본문이 준비된 뒤 스크롤합니다. 이는 파일 단위 점진 렌더링이며 줄 단위 가상화는 아닙니다.

### Problem 02 - 함께 검토할 때 상대가 보고 있는 코드 위치를 알기 어려운 문제

화면을 공유하지 않고 PR을 함께 검토하면 상대가 어떤 파일의 어느 줄을 말하는지 매번 설명해야 합니다. 일반 PR 댓글에는 의견을 남길 수 있지만, 상대가 지금 보고 있는 파일이나 스크롤 위치는 알 수 없습니다.

### Solution 02 - 공동 리뷰방에서 코드 위치와 대화를 함께 공유

별도의 공동 리뷰방에서 참가자가 보는 파일과 스크롤 위치를 공유하고, 코드 줄에 연결된 대화를 나눌 수 있게 했습니다. 이 위치 공유와 대화에는 Socket.io를 사용합니다. 일반 PR 댓글·답글은 PR 상세의 댓글 영역에서 저장·조회하며, 일반 댓글 패널과 알림은 10초 간격으로 새 내용을 확인합니다.

### Problem 03 - 같은 PR의 AI 리뷰가 동시에 실행될 수 있는 문제

사용자가 리뷰를 요청하는 순간 다른 요청도 들어오면, 두 요청이 모두 '진행 중인 리뷰가 없다'고 판단할 수 있습니다. 화면에서 버튼을 비활성화하는 것만으로는 서버의 동시 요청을 막을 수 없습니다.

### Solution 03 - 진행 중인 리뷰를 DB에서 한 건으로 제한

요청 직후 화면에 대기 상태를 표시하고, 서버에서는 진행 중인 리뷰를 먼저 조회합니다. 최종적으로 PostgreSQL의 부분 고유 인덱스가 PR마다 `PENDING` 또는 `IN_PROGRESS` 리뷰를 한 건만 허용합니다. 동시 삽입 충돌은 이미 리뷰가 진행 중인 경우로 처리합니다.

### Problem 04 - PR 기본 정보가 변경 파일 로딩을 기다리는 문제

PR 제목과 상태는 먼저 보여줄 수 있지만, 변경 파일과 코드 차이는 별도 요청이 필요합니다. 이를 한 번에 기다리면 사용자는 기본 정보까지 늦게 보게 됩니다.

### Solution 04 - 기본 정보와 코드 영역의 로딩 분리

서버에서 접근 권한을 확인하며 PR 기본 정보를 읽어 화면에 먼저 전달합니다. 변경 파일은 클라이언트에서 별도로 불러오고, 코드 영역에 자체 로딩·오류 화면을 둡니다. diff 뷰어는 필요할 때 가져와 기본 정보 표시와 파일 표시가 서로를 기다리지 않게 했습니다.
